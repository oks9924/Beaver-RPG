# 개발 AI에게 전달할 지시

현재 개발 단계와 기존 서버·클라이언트 구조를 유지하면서 이 v4 팩을 연결하라. 먼저 기존 에셋 레지스트리와 import_asset_pack.gd를 읽고 실제 내부 ID를 확인한다. 아래 항목을 순서대로 수행한다.

## 병합과 호환

- format_version은 2다. actors[id].animations[state_direction] 단위로 추가·교체한다. 배우 ID 전체를 덮어써서 기존 idle, attack, 보스 기믹을 잃지 않게 한다.
- player_berserker/shaman/engineer는 이번 8상태만 교체한다. 기존 idle을 유지한다. 직업·초상 별칭은 id_mapping.json을 참고한다.
- 일반 적의 요청서 약칭에는 enemy_ 접두사를 붙였다. 내부 별칭을 확인해 한 번만 등록한다.
- vfx_great_tree에는 **active_all 2프레임만 추가**한다. v3 default_all 성장 프레임은 유지한다. 성장 완료 → active_all 루프 → 서버 보호 종료에 제거한다.
- tile_willow_shore는 기존 직선 0~3을 동일 파일로 포함하고 4~11을 추가했다. 프레임 목록은 인덱스 의미와 함께 전체 교체한다.
- ui_card_reward/route는 동일 캔버스 크기의 중앙 투명 프레임이다. content_rect는 ui_layout.json을 읽고 텍스트 컨테이너에 적용한다. 투명 부분 아래의 패널 배경은 클라이언트에서 그린다.
- 새 소품과 아이콘은 default_all이다. NPC는 정면 1장 default_all이다. NPC idle 2프레임이나 4방향이 있다고 가정하지 않는다.

## 재생과 판정

- visual_contact_frame은 0부터 센다. 새 3직업 attack/Q/R은 2, E는 3이다. generic cast는 -1이다.
- 이 값은 그림의 접점이다. 피해·회복·기믹 성공·쿨다운의 판정은 서버 이벤트와 서버 시각에 따른다. 클라이언트 애니메이션 콜백으로 권위 있는 판정을 만들지 않는다.
- walk와 down은 루프, hit·attack·cast 계열은 1회, death는 1회 후 마지막 장을 유지한다. 시전 길이가 다르면 서버 시전 구간에 맞춰 재생 속도를 맞춘다.
- playback_mode=select_frame인 타일 변형·소품·아이콘·UI는 자동 재생하지 않는다. fps=1은 형식 호환용이며 상태를 순환하라는 뜻이 아니다. 물 타일 2장은 2fps 루프다.
- root_bind는 0~3을 재생한 다음 필요하면 마지막 장을 서버 구속 종료까지 유지한다. 회복 구역·포탑 등 지속시간도 서버 상태로 결정한다.
- 두 telegraph는 요청한 예고용 그래픽이다. 실제 공격 도형에 맞춰 배치한다. 링 그림을 충돌체로 쓰거나 장식 VFX의 투명도에서 판정 범위를 추정하지 않는다. geometry_reference.json의 시각 경계 정보를 참고한다.
- 같은 행동을 재접속 스냅샷으로 다시 받으면 소리·VFX를 중복 실행하지 않는다. actor_id+event_id로 중복을 제거하고 현재 서버 상태를 복원한다.

## 지형과 소품

- 모든 새 타일은 64×64 RGBA이며 채워진 지형으로 내보냈다. 벽 뒤의 기존 어두운 바탕 처리와 겹침을 실제 맵에서 확인한다.
- 타일 인덱스는 terrain_indices.json이 기준이다. N/E/S/W는 화면 좌표다. 물가 볼록 모서리는 그 방향에 육지가 차지하는 볼록 사분면, 오목 모서리는 그 방향에서 물이 육지를 파고드는 형태다.
- 습지·뿌리댐 shore ID 2개는 요청서의 '물가 4' 구성에 따라 추가했다.
- prop_boss_*는 독립 물체 상태다. v2 보스 장치 시트와 동시에 겹쳐 그리지 않는다. 기존 IC 기믹의 상태 매핑을 유지하면서 대응하는 물체만 교체한다.
- 프레임 라벨은 시각 상태 설명이다. 문서만 보고 서버의 기믹 성공 조건이나 상태 번호를 바꾸지 않는다. 실제 상태명과 연결한 표를 커밋에 남긴다.
- 이번 팩은 지속 돌진 상태·mark/stagger/wet 스냅샷·다리 배치 규칙 등 요청서가 서버 작업으로 분류한 기능을 구현하지 않는다.

## 오디오

audio_manifest.json은 별도 형식의 오디오 색인이다. 그림 임포터가 오디오까지 지원한다고 가정하지 않는다. Music/Ambience/SFX 버스를 만들거나 기존 버스에 매핑한다. OGG의 LOOPSTART/LOOPEND와 매니페스트의 샘플 위치는 44,100Hz 기준이다. WAV 효과음은 mono, OGG 루프는 stereo다. 자연 녹음과 실제 오케스트라 연주로 표시하지 않는다.

기본 볼륨은 매니페스트 suggested_gain_db를 출발점으로 하되 4인 동시 시전에서 효과음이 포화되지 않도록 실제 게임 믹싱을 한다. 발동·피격 소리는 이벤트에 1회 재생한다. 서버가 켜져 있어도 아무도 듣지 않는 효과음을 서버에서 재생할 필요는 없다.

## 연결 완료 판단

파일 검사 후 직업 3종의 4방향 동작 전환, 적 9종의 사망, 보스 탈피/뿌리 재생, 긴 설명 카드, 맵 직선·볼록·오목 모서리, 소품 상태 전환, 오디오 루프 이음새를 실제 클라이언트에서 확인한다. 기존 1~4인 난이도·기믹 스케일링을 유지하고 중도 합류·재접속에서 시각 상태가 서버와 일치하는지 확인한다. 에셋 연결만으로 보스 기믹이나 게임 시스템 구현이 끝났다고 보고하지 않는다.

문제가 있으면 ID/상태/방향/프레임 번호, 기대·실제 결과, 스크린샷을 qa_results.json에 기록한다. 기존 임시·파생 개수 182개가 모두 해소되었다는 결론은 프로젝트 레지스트리를 실제로 대조한 뒤에만 내린다.
