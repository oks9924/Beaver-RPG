# 《꼬리원정대: 검은 물결》 에셋팩 v1

설치형 클라이언트 RPG 개발에 연결할 **캐릭터 아트·애니메이션 초안**입니다. 원본 시트 25장과 방향/프레임별 투명 PNG 160개를 포함합니다. 완성 게임이나 모든 동작을 갖춘 최종 에셋팩은 아닙니다.

## 포함 범위

| 구분 | 구성 | 개별 PNG |
|---|---|---:|
| 플레이어 5직업 | 기본 자세 × 4방향 | 20 |
| 수호목수 이동 | 4방향 × 4프레임 | 16 |
| 수호목수 기본 공격 | 4방향 × 4프레임 | 16 |
| 수호목수 Q/E/R 시전 | 3동작 × 4방향 × 4프레임 | 48 |
| 일반 몬스터 12종 | 기본 자세 × 4방향 | 48 |
| 보스 3종 | 기본 자세 × 4방향 | 12 |
| 합계 | 20캐릭터, 25원본 시트 | **160** |

수호목수, 톱니전사, 솔방울사수, 수액주술사, 물길공학자의 기본 자세가 포함됩니다. 일반 적은 수액달팽이, 가시멧돼지, 갑각병정, 먹그늘까마귀, 포자버섯, 뿌리인형, 갈대창개구리, 물길거머리, 늪등불나방, 톱턱장수풍뎅이, 톱니집게게, 수액토템입니다. 보스는 철턱 가재, 늪등불 두꺼비, 뿌리왕입니다.

## 빠르게 확인

1. 압축을 풉니다.
2. `beaver_assets/preview.html`을 엽니다. 네트워크나 별도 설치 없이 로컬 이미지와 애니메이션을 확인합니다.
3. 캐릭터·동작·배경·재생 속도를 바꾸어 봅니다. 공격/스킬의 반복 재생은 미리보기 전용입니다.
4. Godot 프로젝트에 최상위 `beaver_assets` 폴더를 복사합니다. 리소스 경로는 `res://beaver_assets/` 기준입니다.

`preview.html`은 개발자가 그림을 확인하는 도구입니다. 게임의 설치형 클라이언트 + 독립 전용 서버 요구는 그대로 유지됩니다.

## 파일 규칙

```text
beaver_assets/
  assets/characters/guardian/{idle,walk,attack,skill_q,skill_e,skill_r}/down_00.png
  assets/characters/{berserker,ranger,shaman,engineer}/idle/down_00.png
  assets/enemies/<enemy_id>/idle/down_00.png
  assets/bosses/<boss_id>/idle/down_00.png
  source_sheets/                    # 고해상도 원본 시트 25장
  godot/resources/<actor_id>.tres   # AnimatedSprite2D용 SpriteFrames 20개
  godot/BeaverVisual.gd             # 시각 표현 연결 예제
  manifest.json                    # 에셋 ID·규격·경로·FPS·소스 영역
  generation_prompts.json          # 이번 생성 프롬프트와 제작 방식
  preview.html                     # 로컬 검수 화면
  DEVELOPMENT_HANDOFF.md           # 개발 에이전트에게 전달할 지시
  QA_REPORT.md                     # 검증 결과와 남은 작업
```

방향 이름은 `down`, `right`, `up`, `left`이고 번호는 `00`부터 시작합니다. 원본 기준 시트는 위왼쪽=down, 위오른쪽=right, 아래왼쪽=up, 아래오른쪽=left입니다. 애니메이션 시트는 위에서부터 down/right/up/left 행, 왼쪽부터 0~3 프레임입니다. 원본은 그림이 격자를 넘는 부분이 있어 균등 분할하지 않았습니다. 분할 영역은 `manifest.json`의 `source_sheets[].frames[].source_rect`에 기록했습니다.

개별 PNG 규격은 플레이어·일반 적 128×128 RGBA, 보스 512×512 RGBA입니다. 원본 PNG는 1254×1254 RGBA입니다. 작은 프레임은 개발에 넣기 쉽게 축소한 것이므로 더 큰 화면에서는 원본을 활용할 수 있습니다.

## Godot 연결

- `AnimatedSprite2D.sprite_frames`에 해당 `.tres`를 지정합니다.
- `BeaverVisual.gd`를 사용하는 경우 Inspector의 `visual_frames`에 지정합니다.
- 일반 캐릭터 기준점은 `(64, 106)`, 보스는 `(256, 424)`입니다. 스프라이트 `centered=false`, `offset=-기준점`으로 노드 위치를 지면 기준점에 맞춥니다. 예제 스크립트가 이를 설정합니다.
- 보스의 512px는 파일 해상도입니다. 월드에서 네 배 크기를 뜻하지 않습니다. 기획한 월드 크기에 맞게 시각 노드의 배율을 조절합니다.
- `idle_down`, `walk_right`, `attack_up`, `skill_q_left`처럼 상태와 방향으로 재생합니다.
- 기본 자세는 1프레임입니다. 이동은 8 FPS, 기본 공격/Q/E는 8 FPS, R은 6 FPS입니다. 이동/대기만 반복합니다. 이 값은 시각 미리보기 출발값이며 밸런스 확정치가 아닙니다.
- 선형 필터를 기본으로 사용합니다. 색상/투명도는 실제 배경에서 다시 확인합니다.
- 4방향 외형과 자유로운 조준 각도는 분리합니다. 무기 궤적·투사체·공격 범위가 반드시 스프라이트 방향에 잠기게 만들지 않습니다.

공격 및 Q/E/R은 서버의 상태 변화 시점에 `play_state(state, direction, true)`로 시작할 수 있습니다. 종료 후 대기로 돌아가는 시점은 캐릭터 상태 머신이 관리합니다. 계속 같은 스킬을 매 프레임 재시작하지 않습니다. 예제는 입력·네트워크·전투·상태 머신을 구현하지 않습니다.

서버는 이미지 크기, 알파 영역, 프레임 인덱스에서 충돌·피해·무적 시간을 추론하면 안 됩니다. 판정은 서버의 스킬 데이터와 시뮬레이션 시간에 둡니다. 이미지/FPS 교체가 공격 속도나 쿨다운을 바꾸지 않아야 합니다.

## 품질 상태와 후속 제작

이번 출력은 **개발 연결용 1차 초안**입니다. 프레임별 얼굴·장비 세부와 신체 비율에 차이가 있고 발 고정·무게감은 추가 보정이 필요합니다. 특히 수호목수의 강한 동작에서는 포즈 사이 크기와 중심 변화가 있습니다. 앵커 값은 연결 기준이며 수작업으로 모든 발 픽셀을 정합했다는 뜻이 아닙니다.

공격/스킬 일부에 작은 이펙트가 몸 이미지와 함께 그려져 있습니다. 이 장식은 판정이나 범위 표시가 아니며, 바닥 예고·실제 보호 구역·충격파·종료 효과 등은 별도 VFX로 구현해야 합니다. Q는 방패 시전 자세, E는 꼬리 타격 자세, R은 시전 자세입니다. 거목의 보호 구역 전체 오브젝트는 포함하지 않습니다.

나머지 4직업의 이동·전투·스킬, 모든 직업의 피격·회피·다운·사망·상호작용, 몬스터/보스의 이동·공격·피격·사망, 보스별 독립 기믹 최소 5개의 전용 연출, NPC·맵·UI·아이콘·사운드는 후속 범위입니다. 기본 자세 4장을 공격 애니메이션이나 보스 기믹 4개로 세면 안 됩니다.

Godot 리소스 경로·PNG 규격·프레임 수는 정적으로 검사하며, Godot 실행·클라이언트 export 검증은 개발 환경에서 해야 합니다. 엔진 실행 확인 없이 완료했다고 기록하지 않습니다.

## 제작 기록

이미지는 내장 이미지 생성 기능으로 제작했습니다. 개별 파일 정리는 원본 그림 경계를 읽어 분할·축소·투명 캔버스 정렬하는 방식입니다. 일부 겹친 사각 영역에서 이웃 프레임의 떨어진 조각만 제거했고, 원본 시트는 보존했습니다. 정확한 신규 생성 프롬프트는 `generation_prompts.json`에 있습니다. 이전 5직업 원본의 정확한 프롬프트는 이번 기록에 다시 만들어 넣지 않았습니다.

외부 다운로드 이미지나 제3자 상표를 추가하지 않았습니다.

Godot 공식 문서: [SpriteFrames](https://docs.godotengine.org/en/stable/classes/class_spriteframes.html), [AnimatedSprite2D](https://docs.godotengine.org/en/stable/classes/class_animatedsprite2d.html).
