# 에셋 도착 전·후 개발 지시

아래 지시를 기존 `비버_4인협동_로그라이크_RPG_제작프롬프트.md`와 함께 개발 에이전트에 전달한다. 기존 마스터 문서가 게임 규칙의 기준이고 이 파일은 에셋 연결 규칙을 보완한다.

## 지금 시작할 작업

기존 MD의 단계 0과 단계 1을 즉시 진행해줘. 설치형 Godot 클라이언트와 독립 전용 서버를 구성하고, 계정 로그인·지속되는 공용 월드·1~4인 원정·이동·기본 공격·재접속의 최소 동작을 검증해줘. 방장이 월드를 생성하는 방식으로 바꾸거나 게임을 웹 브라우저 앱으로 대체하지 마.

에셋이 도착하기 전에는 임시 도형이나 대체 텍스처로 진행해도 된다. 다음 규칙을 처음부터 적용해줘.

1. 플레이어 ID는 `player_guardian`, `player_berserker`, `player_ranger`, `player_shaman`, `player_engineer`로 고정한다. 이름과 경로는 데이터에서 매핑한다.
2. 에셋 로더/레지스트리를 만들고 실제 경로가 없으면 대체 텍스처를 사용한다. 플레이어가 검은 화면이나 로딩 오류에 막히지 않게 한다.
3. 동작 ID는 `idle`, `walk`, `attack`, `skill_q`, `skill_e`, `skill_r`이고 방향은 `down`, `right`, `up`, `left`로 연결한다. 피격/다운/사망 등 아직 없는 동작은 누락 상태를 기록하고 임시 표현을 쓴다.
4. 시각 노드와 서버 충돌/피해 판정을 분리한다. PNG 크기·투명 픽셀·애니메이션 프레임 수를 판정 데이터로 사용하지 않는다. 공격 가능 시각과 피해 활성 구간은 서버의 데이터와 시뮬레이션 시각으로 관리한다.
5. 저장 데이터와 네트워크 메시지는 캐릭터/직업/스킬/외형 ID를 저장한다. 클라이언트 파일 경로나 이미지 바이트를 영구 저장 규칙에 섞지 않는다.
6. 파티는 최대 4인이다. 서버 전체 정원과 원정별 인원을 분리한다. 인원 수에 따른 기믹 변형, 적 구성, 체력·경직·실패 완충은 기존 MD의 규칙을 따른다. 4인이라고 체력만 4배로 만들지 않는다.
7. 보스 기본 공격 패턴과 독립 기믹을 별도 데이터로 관리한다. 4방향 이미지나 공격 포즈를 독립 기믹 수에 포함하지 않는다. 보스당 최소 5개 기믹 요구를 유지한다.
8. 단계별 완료 기준과 실제 검증 결과를 기록한다. 전투·연결이 작동한 부분, 임시 그래픽, 미구현 콘텐츠를 구별한다.

## 이 에셋팩을 받은 뒤

1. `beaver_assets` 폴더를 프로젝트의 `res://beaver_assets/`로 복사한다.
2. `manifest.json`의 캐릭터 ID와 경로를 로더에 연결한다. 기존 코드를 에셋 이름마다 하드코딩해서 분기시키지 않는다.
3. Godot `SpriteFrames` 20개와 개별 PNG 160개를 import한다. 실제 프로젝트에서 리소스 로딩, 발 앵커, 선형 필터, 렌더 순서, 화면 배율을 확인한다.
4. 수호목수 5동작의 4방향 시퀀스를 입력/서버 상태 머신에 연결한다. 공격과 스킬은 단발 재생하고, 서버 시간과 시각 시간이 어긋나면 연출을 보정한다. 시각 프레임에서 서버 피해 이벤트를 직접 발사하지 않는다.
5. 기본 자세만 있는 나머지 캐릭터는 이를 이용해 게임 로직 작업을 계속하되, 이동/공격이 완성된 것으로 기록하지 않는다. 후속 애니메이션은 같은 ID로 교체 가능하게 한다.
6. 몬스터와 보스는 몸 이미지부터 연결한다. 보스별 5개 이상의 기믹 전용 오브젝트·예고·발동·해제 VFX는 기존 기획을 기준으로 별도 구현한다.
7. Windows 클라이언트를 export하여 압축 밖에서도 이미지가 로드되는지 확인한다. 서버 전용 빌드에서는 시각 리소스를 필수로 요구하지 않도록 한다.

## 연결 검수

- 원정 이동 중 방향이 좌우로 뒤집히지 않는가?
- 대기에서 공격으로 전환할 때 지면 기준점이 과하게 튀지 않는가?
- 시각 노드를 축소해도 충돌 반경과 공격 사거리가 바뀌지 않는가?
- 여러 클라이언트에서 같은 공격의 판정·쿨다운은 서버 기준으로 일치하는가?
- 텍스처 누락과 추가 다운로드가 계정 로그인·월드 저장·서버 실행을 막지 않는가?
- 에셋 교체 전후 캐릭터 ID와 저장된 직업·진행도가 유지되는가?
