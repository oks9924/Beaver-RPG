# v3 B~E 검수 보고서

결과: **파일·규격 정적 검사 통과, 게임 엔진 연결 전 작화 초안**.

## 실제로 확인한 항목

- 상세 요청서 B~E의 68개 ID 일치, 개별 게임용 PNG 158장: B 64 / C 53 / D 24 / E 17.
- 모든 게임용 프레임의 디코딩, 요청 크기, RGBA 형식, 경로 존재, 프레임 순서·수, 필수 manifest 필드.
- 빈 영역의 실제 알파 투명, 중복 프레임 해시 없음. 지면을 채우는 바닥·물·물가 면 타일은 불투명 예외.
- 원본 시트 68장 디코딩. 생성 원본은 일부 RGB 면 타일을 포함하고 실제 assets는 전부 RGBA.
- v1·v2·v3-A의 기존 actor ID와 이번 68개 ID 사이에 충돌 없음.
- 정적 상태/변형 배열의 반복 비활성화, 덫·거목 segments의 범위 및 인덱스 검사.
- HP·보스바·초상틀 내부의 투명 영역 검사. HP 채움이 선언된 내부 영역을 벗어나지 않음.
- 자동 검사 799개 통과, 오류 0개. 세부 기록은 qa_results.json.
- preview.html의 JavaScript 구문 검사. 브라우저에서 직접 실행한 검사는 아님.
- 전체 ID 카탈로그, VFX 전 프레임, 타일 연결 샘플, 12px 9-slice 확대, HP 100%/50% 레이어 합성을 이미지로 열어 육안 확인.
- 최종 ZIP CRC와 ZIP 내부 PNG 디코딩 검사.

## 육안 확인 결과와 적용 판단

- 스킬별 모양·색·실루엣과 단계 차이가 구별됨. 덫의 마지막 발동 프레임은 대기 루프에 포함하지 않음.
- 생성된 물가의 색을 바닥·물에 맞춰 한 차례 보정함. 타일 조합 샘플은 qa_previews/terrain_mosaic.png. 물결의 반복 리듬과 타일 간 세부 질감 차이는 남아 있어 엔진에서 최종 확인이 필요함.
- UI 패널·버튼의 12px 9-slice 확대 샘플을 확인함. 장식을 포함한 테두리와 내용의 실제 배치는 게임 해상도에서 조정해야 함.
- HP 틀·채움은 동일 캔버스의 별도 레이어이며 합성 샘플이 포함됨. 보스바는 틀만 제공함.
- 프레임 분리 과정에서 자동 격자 경계를 빈 영역으로 조정했고 미완성 중간 PNG는 제거함. 그림 사이의 크기·윤곽 변화까지 수작업 애니메이션처럼 보정한 것은 아님.

## 엔진에서 남은 검수

Godot 프로젝트, tools/import_asset_pack.gd, 프로젝트 check_assets, 서버·클라이언트 및 데모 실행은 이 작업 공간에서 수행하지 않았음.

1. 효과의 월드 크기·지면 오프셋·실제 캐릭터 시전 시점과의 연결. 생성 이미지의 중심점이 실제 스킬 발생 위치와 자동으로 일치하지는 않음.
2. 소품의 쓰러짐·물 분출·성장 상태 전환에서 상호작용 위치와 렌더링 위치를 확인. 이미지 외곽과 별도의 고정 상호작용 노드를 사용.
3. Terrain Set, 지형 인접 규칙, 충돌·내비게이션 설정. 물가 코너 전용 타일은 이번 요청에 없어 미포함. 다리는 가로/세로 2종 그림이며 긴 다리 구성의 이음새는 연결 시 검수.
4. 공격 예고가 VFX·나무·소품에 가려지지 않는지, 최대 4인 전투에서 효과가 지나치게 겹치지 않는지 확인.
5. UI 글자·아이콘·수치·쿨다운·클릭 상태를 코드로 연결하고 실제 해상도에서 가독성 확인.

## 요청서 수량 해석

요약표의 대략치보다 상세 표를 우선함. 강둑은 설명에 적힌 전체/상하좌우/안쪽 네 모서리를 충족하도록 9장으로 제공. 작업실은 0/1/2단계 3장. UI는 9개 ID이며 상태·변형·레이어를 포함한 PNG는 17장.

대표 GIF는 6종 VFX의 형태 변화 확인용이며 약 7 FPS 공통 속도로 표시함. 정확한 개별 FPS와 상태별 재생 규칙은 manifest.json과 preview.html을 기준으로 사용.
