# v3 B~E 연결 지침

현재 단계 2 코드, v1·v2 및 v3-A 연결 작업을 이어가는 추가 팩입니다. 서버가 판정과 상태를 결정하고 클라이언트가 이번 그림을 표시합니다.

## 1. 공통 규격과 신규 상태명

`format_version: 2`입니다. 요청서에서 B~E에는 개별 상태명이 지정되지 않았으므로 공통 `state: "default"`, `direction: "all"`, `animations.default_all`을 사용했습니다. 파일은 `assets/<id>/default/all_NN.png`입니다. ID는 요청서 그대로입니다.

필수 필드인 `state, direction, fps, loop, frames, hold_last_frame, visual_contact_frame`을 모두 제공합니다. 추가 필드 `frame_labels`는 각 인덱스의 의미, `playback_mode`는 사용 방법, `segments`는 상태별 재생 구간입니다. 임포터가 추가 필드를 무시한다면 아래 표에 맞춰 내부 매핑을 추가합니다.

정적 항목도 임포터 호환성을 위해 양수 FPS를 기록합니다. **FPS가 있다는 이유로 모든 배열을 자동 재생하면 안 됩니다.** 모든 인덱스는 0부터 시작하며 `visual_contact_frame`은 전부 -1입니다. 피해 판정·투사체 생성 시점은 캐릭터 스킬/서버 이벤트가 담당합니다.

| playback_mode | 사용 방법 |
|---|---|
| one_shot | 처음부터 끝까지 1회 재생 후 효과 제거 |
| loop | 해당 서버 상태 동안 반복 |
| select_frame | 성장·손상·장치 진행·UI 상태에 맞는 인덱스 하나 표시 |
| state_sequence | segments의 현재 구간만 재생 |

이 팩의 전체 actor를 추가하되 같은 ID가 있다면 animation 단위로 병합합니다. 기존 에셋 목록이나 저장 데이터를 초기화하지 않습니다.

## 2. VFX

- VFX는 장식입니다. 실제 범위와 공격 예고는 기존 코드 표시를 유지하고, 예고가 VFX에 가려지지 않게 레이어·불투명도·월드 크기를 조절합니다.
- `vfx_thorn_trap`: 설치 `[0]` → 대기 `[1,2]` 반복 → 발동 `[3]`입니다. 0~3 전체를 계속 반복하면 덫이 스스로 발동하는 것처럼 보입니다. 이 때문에 manifest의 전체 loop는 false로 두고 segments에 대기 반복을 명시했습니다.
- `vfx_great_tree`: 성장 `[0,1,2,3,4]` 후 활성 `[5]` 유지/반복. 활성 마지막 1프레임을 유지하며 보호 지속시간은 서버가 정합니다. 별도 흔들림 애니메이션은 없습니다.
- 방패·구조 링·소용돌이·투사체는 루프, 나머지 효과는 단발입니다.
- 솔방울/수액 투사체는 32×32입니다. 화면 크기와 충돌 반경은 따로 설정합니다. 장식 파편을 실제 추가 투사체로 생성하지 않습니다.
- 효과 앵커는 프레임 중심입니다. 상하로 자라는 효과의 지면/캐릭터 부착 위치는 실제 화면에서 오프셋을 조정합니다. 원본을 개별 프레임으로 자를 때 하나의 효과 안에서는 동일한 배율을 사용했습니다.

## 3. 지형과 소품

타일은 64×64이며 물만 2프레임 반복입니다. 나머지는 인덱스 선택입니다. 바닥 4변형을 섞어 사용하고 벽/물/다리는 별도 지형 종류로 연결합니다. 바닥·물은 불투명 RGBA, 벽·다리는 투명 여백을 가진 오버레이입니다.

| ID | 인덱스 순서 |
|---|---|
| tile_willow_wall | 0 전체, 1 북쪽 벽, 2 동쪽 벽, 3 남쪽 벽, 4 서쪽 벽, 5~8 안쪽 NW/NE/SE/SW 모서리 |
| tile_willow_shore | 0 위 풀·아래 물, 1 왼쪽 물·오른쪽 풀, 2 위 물·아래 풀, 3 왼쪽 풀·오른쪽 물 |
| tile_willow_bridge | 0 가로, 1 세로 |
| tile_hub_ground | 0 다진 흙, 1 나무판 |
| prop_gnaw_tree | 0 온전, 1 반쯤 갉힘, 2 쓰러짐 |
| prop_device | 0/1/2/3 = 진행 0/33/66/100% |
| prop_lever | 0 내림, 1 올림 |
| prop_sluice_gate | 0 닫힘, 1 열리는 중, 2 열림 |
| prop_log_cover | 0 온전, 1 파손 |
| prop_hold_point | 0 비활성, 1 활성 |
| prop_memory_tree | 0/1/2 = 성장 1/2/3단계 |
| prop_workshop | 0/1/2 = 업그레이드 0/1/2단계 |

모닥불만 2프레임 반복입니다. 물가의 코너 전용 타일이나 완전한 엔진 Terrain Set/충돌/내비게이션 리소스는 이 이미지 팩에 포함되지 않습니다. 강둑 모서리를 물가 모서리와 혼동하지 않습니다. 원정의 통과·파괴 가능 여부는 그림의 알파 영역에서 추론하지 말고 기존 게임 규칙으로 유지합니다.

소품 크기는 일반 256×256, 기억나무 512×512입니다. 기본 앵커는 각각 (128,212), (256,424)입니다. 물이 쏟아지거나 나무가 쓰러지는 상태에서 그림의 외곽과 실제 바닥 접점이 다르므로 상호작용 지점은 별도 노드로 고정합니다.

## 4. 아이콘

24종 모두 64×64, 정적 1프레임입니다. 스킬·유물·상태효과에 ID별로 연결하고 동일 아이콘으로 다른 효과를 대신하지 않습니다. 아이콘에는 글자·숫자를 넣지 않았습니다. 이름·남은 시간·중첩 수·쿨다운은 클라이언트 텍스트/오버레이로 표시합니다.

## 5. UI

- `ui_panel` 96×96, `ui_button` 96×48: 좌/상/우/하 모서리 여백을 각각 12px로 두는 9-slice입니다. 버튼 인덱스 0 normal, 1 hover, 2 pressed. 상태에 따라 클릭 영역 자체의 크기를 바꾸지 않습니다.
- `ui_card_reward`: 256×352, 0 유물/1 강화. 카드 내용·아이콘·이름·설명은 별도 컨트롤로 표시합니다.
- `ui_card_route`: 256×160, 0 전투/1 사건/2 상점/3 휴식/4 보스. 색 띠와 텍스트/아이콘을 함께 써서 색만으로 구분하지 않게 합니다.
- `ui_bar_hp`: 256×24, 0 틀/1 채움. 두 PNG는 같은 캔버스 좌표에 맞춰져 있습니다. 채움을 뒤에, 틀을 앞에 놓고 채움만 현재 비율에 맞춰 클리핑합니다. 채움 영역은 `fill_rect_px: [17,8,222,9]`이며 오른쪽 절단 위치는 `17 + 222 × 체력비율`입니다. 두 장을 번갈아 재생하지 않습니다.
- `ui_bar_boss`: 512×32의 틀만 있습니다. 보스 수치에 맞는 채움은 UI 코드로 표시합니다. 권장 내부 채움 영역은 `suggested_fill_rect_px: [80,12,354,11]`이고 틀을 앞에 겹칩니다.
- `ui_title_logo`: 1024×512의 문양·빈 리본입니다. “꼬리원정대”는 폰트로 별도 표시합니다.
- `ui_app_icon`: 256×256 PNG. 운영체제 배포용 ico/icns 변환은 클라이언트 패키징 단계에서 합니다.
- `ui_frame_portrait`: 288×288. 투명한 안쪽 공간에 초상을 별도 표시합니다.

## 개발자에게 전달할 지시

이 ZIP은 asset_request_v3.md의 B~E 추가 에셋이다. README.md, ASSET_INDEX.md, QA_REPORT.md와 이 문서를 읽고 기존 v1·v2·v3-A 위에 연결해줘. 정적 상태 배열과 애니메이션을 구분하고, 덫/거목 segments, 체력바 레이어, UI 12px 9-slice, 타일 인덱스 매핑을 반영해줘. 기존 서버 판정과 공격 예고를 유지하면서 효과·소품·HUD에 적용한 뒤 check_assets와 데모 캡처로 검수하고 결과 및 필요한 작화 보정을 보고해줘. F·G는 이번 범위에 없다.
