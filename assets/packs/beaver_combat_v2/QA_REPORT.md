# 전투 애니메이션 v2 검수 기록

상태: **개발 연결용 4프레임 초안**. 그림과 리소스를 제공하며, 실행 가능한 게임 빌드는 아닙니다.

## 파일 검사 결과

| 검사 | 결과 |
|---|---|
| 생성 원본 시트 | 45장, 모두 PNG 읽기 성공 |
| 최종 개별 프레임 | 720개: 신규 660개 + 기존 기본 자세 60개 |
| PNG 형식 | 모두 RGBA, 지정 크기 일치, 투명 픽셀과 완전 불투명 픽셀 존재 |
| 손상·누락 PNG | 0개 |
| 파일 내용 중복 | 720개 SHA-256 모두 다름 |
| 출력 캔버스 테두리 | 알파 32 초과 픽셀 없음 |
| 리소스 | 몸체 15개 + 기믹 장치 15개, 총 SpriteFrames 30개 |
| 애니메이션 항목 | 225개: 기본 자세 60개 + 몸체 동작 120개 + 기믹 상태 45개 |
| 프레임 수 | 기본 자세는 방향당 1개, 모든 새 동작은 방향/상태당 4개 |
| 단발 설정 | 모든 전투·기믹 동작 loop=false |
| Godot 리소스 경로 | 참조 PNG가 모두 존재함 |
| 기믹 ID 연결 | 15종 모두 보스·장치·진행/성공/실패 리소스와 연결됨 |
| 미리보기 JavaScript | Node 구문 검사 통과 |
| GIF 미리보기 | 948×664, 4프레임, 전체 프레임 읽기 성공 |

원본 30장의 몸체 동작을 분할한 뒤 알파 면적도 비교했습니다. 이웃 그림 제거 과정에서 몸체가 대량으로 삭제된 사례는 없었으며, 원본 크롭의 알파 면적과 크기 변환을 기준으로 한 가장 낮은 비율은 약 98.6%였습니다. 이는 분할 누락 검사이며 작화 품질이나 애니메이션의 자연스러움을 수치로 보증하는 검사는 아닙니다.

기믹 15종의 진행·성공·실패 대표 프레임과 보스 3종의 공격 대표 프레임을 어두운 배경 위에서 육안 확인했습니다. 원본의 색 배경 문제는 해당 시트를 다시 제작해 해결했습니다. 최종 장치 그림은 서로 분리되어 있고 지정 캔버스 안에 배치되어 있습니다.

자동 검사 세부 결과는 `qa_results.json`에 있습니다. 압축 파일은 생성 후 CRC와 내부 PNG 전체 읽기를 별도로 확인합니다.

## 실제 프로젝트에서 확인할 부분

- 이 환경에서 Godot import, GDScript 실행, Windows 클라이언트 export, 서버 접속 테스트는 수행하지 않았습니다. `.tres`는 경로·텍스트 구조를 확인한 연결 자료입니다.
- HTML 미리보기는 구문 검사를 했으며 브라우저에서 실제 실행한 결과는 아직 없습니다. GIF와 PNG는 별도로 읽고 확인했습니다.
- 각 동작은 4프레임 키포즈입니다. 프레임 사이의 몸 비율·발 위치·방향 표현이 조금씩 달라질 수 있으며, 출시 전 게임 카메라와 배경에서 보정해야 합니다.
- 보스 시전과 약점 노출 몸체는 기믹들이 공유합니다. **기믹 15개의 구별은 전용 장치 연출과 게임 로직에서 이루어집니다.** 기본 공격 12개를 기믹 수에 합산하지 않았습니다.
- 장치가 정화·잠금 해제되는 그림은 서버의 성공 판정을 대체하지 않습니다. 상태를 자동 순환시키지 말고 서버 이벤트와 진행률을 연결해야 합니다.
- 운반 물체와 넓은 전장 효과는 개별 노드로 구현할 부분입니다. 조합형 장치 그림을 독립 이동 가능한 여러 오브젝트로 오인하지 않도록 `INTEGRATION.md`를 함께 전달하세요.
