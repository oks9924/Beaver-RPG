# 단계 5 실기 검증 절차서 (친구 4대 PC)

기획서 19절 단계 5 와 20절 완료 판정 중 **사람이 실제로 해야 하는 항목**만 모았다. 자동화된 항목(단위·통합·봇)은 `docs/verification.md` 에 있다. 한 PC 의 여러 클라이언트, LAN 의 여러 PC, 외부 인터넷의 다른 PC 를 구별해 기록한다.

## 준비
1. GitHub Release `v0.2.0`(또는 최신 CI `dist` 아티팩트)에서 `TailExpedition-windows.zip` 과 `linux-server` 묶음을 받는다.
2. 서버: `docs/deploy.md` 대로 설치. 보안 그룹 UDP 7777. 인터넷 공개는 DTLS 가 없으므로 친구끼리 VPN(Tailscale 등) 권장.
3. 클라이언트 4대: zip 을 풀고 `TailExpedition.exe` 실행 → 서버 주소 입력. 버전이 다르면 접속 전에 `VERSION_MISMATCH` 안내가 떠야 한다.

## 인원별 밸런스 보고 양식 (20절)
같은 난이도·같은 내실 조건에서 기록한다. 소수의 성공 사례로 균형을 결론내리지 않는다.

| 날짜 | 인원 | 직업 조합 | 난이도 | 시도 | 보스 | 처치 시간 | 다운 | 기믹 성공/등장 | 조작에 쓴 시간 | 대기 시간 | 클리어 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | | |

기믹별로: 등장·완료·실패·재사용 횟수, 아무 행동도 못 한 대기 시간, 기믹 성공으로 절약한 시간, 실제 체험한 독립 기믹 수. 15기믹 × 4인원 중 실제 해 본 조합에 표시하고 나머지는 미검증으로 남긴다.

## 플레이 관찰로 고칠 것 (기획서 단계 5)
- 불명확한 공격 예고 → 예고 시간·색·모양 (`data/enemies.json`, `bosses.json`, 클라이언트 `world_view.gd`)
- 지루한 방 → 웨이브 예산·방 유형 풀 (`rooms.json`, `regions.json`), `docs/playtest_notes.md` 의 대응안
- 선택되지 않는 유물 → `relics.json` 수치·시너지
- 한 직업의 과도한 우세 → `classes.json`, `upgrades.json`, 상한(`rules.json: caps`)

## 보고
결과는 `docs/verification.md` 의 "실기 검증" 절에 날짜·환경(같은 PC / LAN / 인터넷)과 함께 적는다. 통과하지 못한 항목은 미검증으로 남기고, LAN 성공을 인터넷 검증으로 적지 않는다.
