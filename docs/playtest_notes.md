# 플레이 관찰과 대응안

## 2026-09-20 · 사용자 1인 실기 (v2 연결 빌드)

관찰: 보스 처치까지 약 5분. 기믹이 단순함. 방마다 적이 적음.

### 현재 수치 (왜 5분인가)
| 항목 | 현재 값 | 효과 |
|---|---|---|
| 경로 | 5층 중 전투 2~3방, 나머지 사건·상점·휴식 | 실제 전투 시간이 짧다 |
| 일반 방 웨이브 | 섬멸 2회, 거점·장치 3회, 기준 예산 6~7 (달팽이 위협 1.0, 멧돼지 1.6, 까마귀 1.4) | 1인 기준 방당 적 6~9마리 |
| 적 체력 | 달팽이 40, 멧돼지 55, 까마귀 45 / 망치 12 | 3~5타에 죽는다 |
| 보스 체력 | 520 (1인), 갑각 파괴 시 받는 피해 +18%씩 | 1인 DPS 약 12로 60~90초 |
| 기믹 | 전투 시작 후 12초 간격으로 1개씩, 각 12~40초 | 보스 체력이 먼저 바닥나 기믹 2~3개만 본다 |
| 기믹 실패 벌칙 | 1~2인은 `limited_damage`(제한 피해) | 실패해도 흐름이 안 바뀐다 |

### 대응안 (수치는 데이터 파일만 바꾸며, 실제 플레이로 재확인)
1. **경로를 전투 중심으로**: `regions.json` 층을 5 → 7 로 늘리고 전투 4방 + 정예 1방 + 사건/상점/휴식 각 1 을 보장한다. 정예방(체력 2배·강공격 적 1 + 호위)은 새 방 유형이다.
2. **방당 적 밀도**: 기준 예산 6 → 9, 웨이브 2 → 3, 다음 웨이브 조건 "1마리 이하" → "3마리 이하"로 겹치게 한다. 목표: 1인 방당 적 12~15마리, 4인 25~30마리. 적 체력은 유지하고 수로 늘린다(가독성 유지).
3. **방 유형 4종 채우기**: 섬멸·거점·장치 + **호위**(목재 뗏목을 강 건너로 밀며 적을 막기)를 추가한다. 기획서의 "완료 조건이 다른 일반방 4가지" 조건.
4. **보스 체력과 기믹 순서**: 보스 체력 520 → 900(1인), 갑각 파괴 없이는 받는 피해 -40%(갑각 3조각을 깨야 정상 피해). 단계 전환(65%·30%)마다 기믹을 **강제 1개** 넣고, 5개 기믹을 최소 4개는 보게 한다. 기믹 간격 12초 → 9초.
5. **기믹 실패의 무게**: 1~2인도 실패 시 `extra_adds`(추가 적 2) + 보스 체력 5% 회복. 성공 시 갑각 1조각 파괴로 보상이 눈에 보이게.
6. **기믹 복잡도**: IC-01 지지목 1개 → 2개(1인도 순서 선택), IC-02 수문 표식을 매 8초 바꿈, IC-05 잔해 제거 뒤 밧줄 고정까지 두 단계 유지. 기믹 중에도 기본 패턴 1개(집게)는 계속 나온다.
7. **목표 시간**: 1인 12~15분, 4인 15~25분. 봇 자동 플레이로 방당 시간을 측정해 `docs/verification.md` 에 기록한다.

적용 여부와 순서는 사용자 결정 후 진행한다.

### 적용 기록 (2026-09-21, v0.3.0)
사용자 지시("대중적인 로그라이크 방식을 조사해 난이도·몹·스킬을 재구성")로 대응안 2·4·5 를 적용하고, 조사한 표준 규칙(디렉터 증원·시간 위험도·서약·정예 접두·희귀도/리롤·제단·휴식 선택·시간 문)을 더했다. 상세는 `docs/roguelike_design.md`. 대응안 1(경로 7층)·3(호위)은 4단계에서 이미 반영(3지역 18층, 호위방). 6(기믹 복잡도)은 미적용.

### 적용 기록 (2026-09-21, 적 밀도·마을 메뉴)
- 사용자 지적 "로그라이크치고 몹이 너무 적다": 섬멸 예산 14·4웨이브·다음 웨이브 조건 생존 ≤4, 거점/장치 +4, 정예 +3, 디렉터 예비 0.9·초당 0.12, 화면당 상한 12(+5/추가 인원). 봇 기준 방당 출현 수 솔로 23~25, 4인 43~46 (`docs/roguelike_design.md` 밀도 표). 캡처: `docs/screenshots/room_density_4p.png`.
- 사용자 지적 "마을 내실창이 너무 길어 화면을 가린다": 좌측 패널은 마을 정보·접속자·한 줄 요약·메뉴 단추 6개만 남기고, 내실·마을 복구 / 숙련·특성 / 도감·기록 / 퀘스트·인연은 가운데 **마을 메뉴** 창(Tab 또는 단추, Esc 닫기)의 탭으로 옮겼다. 설정·로그아웃도 메뉴에 있다. 퀘스트 탭은 NPC 대화 전에도 계정 진행에서 목록을 만든다. 캡처: `docs/screenshots/hub_v5_compact.png`, `hub_menu_village.png`, `hub_menu_mastery.png`, `hub_menu_quest.png`.

### 적용 기록 (2026-09-21, 던파식 던전 격자)
- 사용자 요청: 시작 방 → 보스 방으로 이어지는 던파식 던전. 결정: 문으로 걸어서 이동(전원 3초·과반 10초), 되돌아가기 허용, 5×3 격자에 9~11방, 장비 시스템과 병행.
- 봇 검증: 통합 42/42(2인 파티가 첫 방 클리어 뒤 문을 통과해 2번째 방 진입), 4인 수호목수 봇 파티는 시작 방(43마리) 클리어 → 문 이동 → 거점/호위 방에서 전멸. 봇은 거점·호위 목표에 약하며 밀도 상향과 겹쳐 있어 실기에서 방 2 난이도를 확인해야 한다.
- 캡처: `docs/screenshots/dungeon_explore.png`(클리어 뒤 문 열림 + 격자 지도), `dungeon_next_room.png`(서쪽 문으로 입장한 다음 방).

### 적용 기록 (2026-09-21, 영구 장비 1차)
- 결정: 영구 장비, 등급 5단계(+1줄/등급, 전설 고유), 드랍·장착 먼저, 장신구 2슬롯, 직업당 무기 2종. 데이터 `data/equipment.json`(무기 10·갑옷 3·장신구 4·등급·드랍·상한), `data/affixes.json`(특성 50·고유 9).
- 마을 메뉴에 장비 탭. 원정 준비 중에도 장착 변경 가능(준비 완료 시 서버가 다시 합산).
- 봇 검증: 4인 파티 1방 클리어(46마리) 뒤 4명 중 1명의 창고에 일반 장신구가 저장됨(25% 굴림). 데모: 창고 항목 클릭 → 서버 EQUIP → 계정 저장 → 장착 표시(`docs/screenshots/hub_menu_gear.png`, `hub_menu_gear_equipped.png`). 실기에서 확인할 것: 무기별 손맛(통나무·대톱·투척기), 상한이 유물 빌드를 가리지 않는지.

### 적용 기록 (2026-09-21, 장비 강화·재감정·분해)
- 재료 수액 결정: 분해(1/2/5/12/30 + 강화 단계), 정예 +1, 보스 +3. 강화 +1~+5 기본 속성 +10%/단계, 재감정은 줄 선택 후 같은 계층에서 재굴림. 장비 탭에 상세 패널(장착·강화·재감정 줄 버튼·분해).
- 확인할 것: 결정 수급 속도(보스 3개면 전설 재감정 1회에 5보스 필요 — 느리면 분해 값을 올린다).

### 적용 기록 (2026-09-21, 강화 3단계 결과·제작 도안)
- 사용자 결정: 강화는 성공/실패(재료만 소모)/파괴 3단계, 성공률은 저강화에서 높고 점점 낮아지며(95→40%) 파괴는 1% 고정.
- 제작 도안 9종(고급 3 기본, 희귀·영웅 6은 보스 처치 해금). 비용 결정 4/10/24 + 기억 조각 2/5/12.
- 확인할 것: +5 도전 기대 시도 수 ≈ 2.5회(비용 18×계수)라 전설 +5 는 결정 100개 안팎. 파괴 1% 는 5단계 전부 도전 시 누적 약 4~5%.

### 적용 기록 (2026-09-21, 가독성 패스)
- 사용자 지적 "전체적으로 가독성이 떨어진다". 적용: 모든 글자에 어두운 외곽선 3px(테마: Label·Button·RichTextLabel·LineEdit·OptionButton), 글자 크기 하한 14px(11~13px 사용처 전부 상향), 흐린 회색 안내 글자 밝기 보정(`UIKit.readable_color`), 패널 나무결 살짝 어둡게(대비), 패널 안쪽 여백 확대, 월드 글자(이름표·문 안내·지도)도 외곽선, 긴 안내문 자동 줄바꿈, 장비 버튼 글자 잘림(…) 처리, 데모 캡처에서 개발 정보 숨김.
- 기본 UI 배율은 1.0 유지(1.15 는 1280×720 에서 우측 패널이 밀림). 설정 → "텍스트·UI 크기"로 1.6 까지 올릴 수 있다.
- 남은 과제: 아이콘 없이 글자로만 구분하는 부분(장비·도안)은 v5 아이콘이 들어오면 줄어든다. 실기(1920×1080)에서 글자 크기 재확인.
